AI Gateway

Safety by architecture, not by prompt.

L1 Input guard
  • ·Dates, SSNs, phone numbers redacted from audit logs
  • ·Scans nested JSON fields for prompt injection — not just surface text
  • ·Flags attacks, never silently drops a request
→
L2 Safety preamble
  • ·Role boundary prepended to every call, loaded once at startup
  • ·Three few-shot refusal examples: medical advice, medication adjustment, diagnosis
  • ·Model sees the correct refusal shape before it responds
→
LLM
call
→
L3 Output scanner
  • ·Pydantic schema validation first — cheapest check, fails fast
  • ·Banned-phrase regex scanner — deterministic, no hallucination risk
  • ·Retry prompt names the exact phrase that triggered the block
Mode A Structured citations — Summary
  • ·Every number must include a citation object with a source record UUID
  • ·Verifier looks up each UUID and checks the value (±0.5% tolerance)
  • ·One unverifiable value → entire output rejected and retried
Mode B Parse and match — NLQ & Observations
  • ·Every number extracted from prose and matched against patient records
  • ·Decimals: ±0.5% tolerance · Integers: exact match required
  • ·Value not in the retrieval set → retry

The LLM cannot fabricate a biomarker value and have it reach the user — it either cites a real record, or the output is rejected.
